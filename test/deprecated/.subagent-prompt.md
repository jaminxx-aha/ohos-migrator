# Subagent task: rewrite one deprecated-API probe .ets file into real runtime code

## Background
This HarmonyOS project at `e:\code\deprecated` contains ~147 `.ets` "probe" files under `entry/src/main/ets/` (names like `ohos-*.ets`, `system-*.ets`). Each file exists so that `scan-deprecated.js` (in the project root) can compile it with DevEco's TypeScript compiler and report the full metadata of every `@deprecated` API that the file *uses*. Currently each probe line is trivial, e.g.:

```
import pasteboard from '@ohos.pasteboard';
declare let _v0: pasteboard.PasteData; _v0.addHtmlRecord('');
declare let _v1: pasteboard.PasteData; _v1.addTextRecord('');
```

These are type-only `declare let` stubs whose only job is to make the compiler *see* a usage of each deprecated API. The user wants each file rewritten into **realistic runtime code** — real parameter values, `async`/`await` for async APIs, `try`/`catch`, and calls organized into a coherent business scenario — instead of trivial stubs.

## Your task (one file)
Rewrite the single file assigned to you. Steps:

1. **Read the file** at the given path.
2. **Capture current coverage.** Run, from the project root `e:\code\deprecated`:
   ```
   node scan-deprecated.js <relative-path> --json
   ```
   This prints `deprecatedCount` and a `hits` array. Each hit has `qualifiedName` (e.g. `SystemPasteboard.setPasteData`) and `callee`. **This is the set of deprecated APIs the file currently exercises — you MUST preserve every one of them.** Save the list of `qualifiedName`s (dedup) — call this the "coverage set".
3. **Rewrite the file** into real runtime code:
   - KEEP the top import line unchanged.
   - Remove all `declare let _vN: ...;` stubs.
   - Obtain instances of classes via the module's real factory/creation APIs (e.g. `pasteboard.createPlainTextData(...)`, `rdb.getRdbStore(...)`) instead of `declare let`.
   - Use realistic parameter values (real strings, real table names, realistic enum values, real MIME types, etc.).
   - For asynchronous APIs, use `async`/`await` and wrap in `try`/`catch` with realistic error handling (log via `console.error`/`hilog`-style comments are not needed; a simple `catch (e) { /* handle */ }` is fine, or `console.error('msg', e)`).
   - Organize calls into a small number of cohesive `async function`s named after a real business scenario (e.g. `async function copyTextToClipboard()`, `async function queryUserByAge()`). You may add a thin entry `async function run() { ... }` that calls them, and `run();` at the end is NOT required (top-level await is fine in .ets module scope? — to be safe, wrap everything in functions and call the entry function).
   - **Every deprecated API from the coverage set MUST still appear in the rewritten file** as a real call/property-access that the compiler resolves to the same symbol. Preserve enum/property accesses too (e.g. `rdb.SyncMode.SYNC_MODE_PULL`, `pasteboard.ShareOption.CROSSDEVICE`).
   - Do NOT introduce deprecated APIs that were NOT in the original file (no new `@deprecated` symbols — keep the file's coverage set stable).
   - The code should be type-correct against the SDK `.d.ts` so it would compile. If you cannot obtain a required instance realistically without adding non-deprecated setup calls, that's fine — non-deprecated setup calls are allowed; only deprecated ones must stay within the original set.
4. **Verify coverage.** Re-run `node scan-deprecated.js <relative-path> --json`. Compare the new `qualifiedName` set to the original:
   - If any original qualifiedName is now MISSING → you lost coverage; fix the file so it reappears (re-add that call in a realistic spot).
   - If NEW deprecated qualifiedNames appeared that weren't in the original → you accidentally pulled in a new deprecated API; rework to remove it (e.g. use a non-deprecated alternative for setup, or drop that call).
   - Iterate until the coverage set matches the original exactly (same set; counts may differ if one API is touched multiple times — that's acceptable, prefer exactly once).
5. **Report back** concisely: file path, original deprecated count, final deprecated count, and a one-line summary of the scenarios you wrote. Do NOT paste the whole file.
